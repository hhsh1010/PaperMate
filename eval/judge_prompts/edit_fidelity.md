# 改稿保真（Edit Fidelity）评测 Prompt

用于 A3 评估「`/改稿` 工作台的段落改写是否**保住了原文事实**、且**真的执行了指令**」。
配套 `faithfulness.md`（管"有没有编"）与 `abstention.md`（管"没有就说没有"）——
本判官管的是第三条：**改写后是不是还是同一件事**。

建议使用**跨厂商、temperature=0** 的裁判模型（与主模型不同源，避免自夸偏差）。

## 为什么改稿要单独一个判官

改稿与问答的失败模式**不一样**：
- 问答失败 = 编造了资料里没有的内容（faithfulness 能抓）；
- 改稿失败 = **把原文的数字/结论改错了**、或**表面改写实则没执行指令**。

第二类尤其危险：`77.4%` 被"润色"成 `74.7%`、`提升了 2.9 个百分点` 变成 `提升到 2.9 个百分点`，
文本读起来**通顺得像对的**，靠人眼抽查极易漏过。而这类错误会直接写进用户的论文。

## 输入
- `instruction`：用户下的改写指令（如「扩写」「缩写」「润色」「去重」及自定义要求）。
- `before`：改写前的原文段落。
- `after`：改写后的段落。

## 裁判 Prompt
```
你是一个严谨的评测员，负责判断【改写后】文本是否忠实地完成了【改写指令】。

改写指令：
{instruction}

改写前：
{before}

改写后：
{after}

请依次检查三项，任一不满足即判 false：
1. **事实保真**：改写后不得改变原文的数值、单位、结论方向、主体对象。
   特别核对：百分比、倍数、样本量、年份、模型/方法名称、指标名（如 mAP、FPS）。
2. **指令执行**：改写后确实体现了指令要求（「缩写」应变短、「扩写」应更详细、「去重」不应保留重复表述）。
3. **未越界**：不得添加原文没有的事实、数据或结论（可以调整措辞与结构，不可以添加信息）。

仅输出一个 JSON：{"faithful": true|false, "violations": ["逐条列出违反项，无则空数组"], "reason": "简要说明"}
```

## 判定规则
- `faithful = true` 且仅当三项全部满足。
- **数值/单位被改动 → 一律 false**（哪怕改动很小；这正是本判官存在的首要理由）。
- 措辞、语序、分段结构的调整**不算**违规（改写的本意就是换表达）。
- 聚合：edit_fidelity@N = N 条样本中 faithful=true 的比例。

## 备注
- 判官只做**判定**，不负责改稿；判 false 时 `violations` 应给出可定位的条目（便于回流）。
- 与其它判官一致：**失败样本（ok=False）不计入分母**，但必须在结果里单独暴露条数。
